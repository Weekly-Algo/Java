# 프로그래머스 — 다리를 지나는 트럭

## 1. 문제 한눈에 보기

여러 대의 트럭이 **입력된 순서대로 한 차선 다리**를 건너려고 한다.

다리에는 두 가지 제한이 있다.

1. 다리 위에는 최대 `bridge_length`대의 트럭만 올라갈 수 있다.
2. 다리 위 트럭들의 무게 합은 `weight` 이하여야 한다.

트럭은 1초마다 한 칸씩 이동하며, 다리에 올라온 트럭 한 대가 다리를 완전히 건너는 데에는 `bridge_length`초가 걸린다.

모든 트럭이 다리를 완전히 건너는 데 필요한 최소 시간을 구하는 문제이다.

---

## 2. 매개변수의 의미

```java
solution(int bridge_length, int weight, int[] truck_weights)
```

| 매개변수 | 의미 |
|---|---|
| `bridge_length` | 다리의 길이이자 다리 위에 동시에 존재할 수 있는 최대 트럭 수 |
| `weight` | 다리가 견딜 수 있는 최대 무게 |
| `truck_weights` | 다리를 건너려는 트럭들의 무게. 배열 순서대로 진입해야 함 |

예를 들어 다음과 같은 입력이 있다고 하자.

```text
bridge_length = 2
weight = 10
truck_weights = [7, 4, 5, 6]
```

- 다리는 길이가 2이므로 트럭 한 대가 건너는 데 2초가 걸린다.
- 다리 위 트럭들의 무게 합은 10을 넘을 수 없다.
- 트럭은 반드시 `7 → 4 → 5 → 6` 순서로 진입해야 한다.

---

## 3. 문제에서 어려운 부분

이 문제에서는 단순히 트럭 무게만 확인하면 안 된다.

매초 다음 내용을 함께 관리해야 한다.

- 어떤 트럭이 다리에서 빠져나가는가?
- 현재 다리 위 무게는 얼마인가?
- 다음 트럭이 지금 진입할 수 있는가?
- 진입하지 못한다면 시간이 흐른 것을 어떻게 표현할 것인가?

따라서 실제로 시간이 흐르는 것처럼 상태를 바꾸는 **시뮬레이션**이 필요하다.

그리고 다리 위 트럭은 먼저 들어온 트럭이 먼저 빠져나가므로 **큐(Queue)**를 사용하기 좋다.

---

## 4. 핵심 자료구조: 큐

### 4.1 큐란?

큐는 먼저 들어온 값이 먼저 나오는 자료구조이다.

```text
먼저 들어온 값 → 먼저 나감
```

이를 FIFO(First In, First Out)라고 한다.

트럭도 먼저 다리에 들어온 순서대로 빠져나가므로 큐의 동작과 잘 맞는다.

### 4.2 Java 큐의 주요 메서드

| 코드 | 의미 |
|---|---|
| `bridge.offer(value)` | 큐의 뒤에 값을 추가 |
| `bridge.poll()` | 큐의 맨 앞 값을 꺼내면서 제거 |

---

## 5. 다리를 고정 길이 큐로 표현하기

다리 길이가 2라면 크기가 2인 큐로 다리를 표현한다.

```text
[다리 출구 쪽, 다리 입구 쪽]
```

트럭이 없는 빈 공간은 `0`으로 나타낸다.

처음에는 다리 위에 트럭이 없으므로 다음과 같이 만든다.

```text
[0, 0]
```

매초 다음 작업을 한다.

1. 큐 맨 앞의 값을 하나 제거한다.
2. 다음 트럭이 진입할 수 있으면 큐 뒤에 트럭 무게를 넣는다.
3. 진입할 수 없으면 큐 뒤에 `0`을 넣는다.

예를 들어 다음과 같이 변화한다.

```text
[0, 0]  처음 상태
[0, 7]  트럭 7 진입
[7, 0]  다음 트럭은 진입하지 못하고, 트럭 7만 이동
[0, 4]  트럭 7 퇴장, 트럭 4 진입
```

큐의 크기가 항상 `bridge_length`로 유지되기 때문에, 트럭이 큐에 들어간 뒤 정확히 `bridge_length`초가 지나면 맨 앞에서 빠져나오게 된다.

즉, 큐 자체가 다리의 길이와 트럭의 이동 시간을 모두 표현한다.

---

## 6. `0`을 넣는 이유

`0`은 트럭의 무게가 아니라 **트럭이 없는 빈 공간**을 뜻한다.

다음 트럭이 무게 제한 때문에 진입하지 못해도 시간은 1초 흐르고, 이미 다리 위에 있는 트럭은 한 칸 이동해야 한다.

이때 큐 뒤에 `0`을 넣으면 다음 두 가지가 모두 표현된다.

- 새로운 트럭은 다리에 진입하지 못함
- 기존 트럭은 1초만큼 이동함

따라서 `0`은 이 문제에서 **빈 1초** 또는 **빈 다리 한 칸**이라고 이해하면 쉽다.

---

## 7. 알고리즘 순서

1. 큐에 `0`을 `bridge_length`개 넣어 빈 다리를 만든다.
2. 시간, 현재 다리 무게, 다음 트럭의 인덱스를 0으로 초기화한다.
3. 1초가 흐를 때마다 큐의 맨 앞 값을 제거한다.
4. 제거된 트럭 무게를 현재 다리 무게에서 뺀다.
5. 다음 트럭을 추가해도 무게 제한을 넘지 않는지 확인한다.
6. 진입할 수 있으면 트럭을 큐에 넣고 다음 트럭으로 이동한다.
7. 진입할 수 없으면 큐에 `0`을 넣는다.
8. 모든 트럭이 다리에 진입할 때까지 반복한다.
9. 마지막 트럭이 다리에서 빠져나가는 데 필요한 `bridge_length`초를 더한다.

---

## 8. Java 정답 코드

```java
import java.util.LinkedList;
import java.util.Queue;

class Solution {
    public int solution(int bridge_length, int weight, int[] truck_weights) {
        Queue<Integer> bridge = new LinkedList<>();

        // 트럭이 없는 빈 다리를 만든다.
        for (int i = 0; i < bridge_length; i++) {
            bridge.offer(0);
        }

        int time = 0;
        int currentWeight = 0;
        int truckIndex = 0;

        // 모든 트럭이 다리에 진입할 때까지 반복한다.
        while (truckIndex < truck_weights.length) {
            time++;

            // 다리의 맨 앞에 있는 트럭 또는 빈 공간을 제거한다.
            int exitedTruck = bridge.poll();
            currentWeight -= exitedTruck;

            int nextTruck = truck_weights[truckIndex];

            // 다음 트럭까지 올라가도 무게 제한을 넘지 않는 경우
            if (currentWeight + nextTruck <= weight) {
                bridge.offer(nextTruck);
                currentWeight += nextTruck;
                truckIndex++;
            } else {
                // 진입할 수 없으면 빈 공간을 추가한다.
                bridge.offer(0);
            }
        }

        // 마지막 트럭이 다리에 진입한 뒤 빠져나가는 시간
        return time + bridge_length;
    }
}
```

## 9. 코드 자세히 해석하기

### 9.1 큐 생성

```java
Queue<Integer> bridge = new LinkedList<>();
```

다리 위의 각 칸을 저장할 큐를 만든다.

큐 안에는 다음 값이 들어갈 수 있다.

- 양수: 해당 무게의 트럭
- `0`: 트럭이 없는 빈 공간

---

### 9.2 빈 다리 만들기

```java
for (int i = 0; i < bridge_length; i++) {
    bridge.offer(0);
}
```

다리 길이만큼 `0`을 넣어 빈 다리를 만든다.

다리 길이가 2라면 다음 상태로 시작한다.

```text
[0, 0]
```

이후 매초 하나를 빼고 하나를 넣으므로 큐의 크기는 항상 `bridge_length`로 유지된다.

---

### 9.3 상태 변수

```java
int time = 0;
int currentWeight = 0;
int truckIndex = 0;
```

| 변수 | 역할 |
|---|---|
| `time` | 지금까지 흐른 시간 |
| `currentWeight` | 현재 다리 위 트럭들의 무게 합 |
| `truckIndex` | 다음에 다리에 진입해야 할 트럭의 배열 인덱스 |

`truckIndex`가 0이면 다음 트럭은 `truck_weights[0]`이다.

트럭이 한 대 진입할 때마다 `truckIndex++`를 실행한다.

---

### 9.4 반복 조건

```java
while (truckIndex < truck_weights.length) {
```

아직 다리에 진입하지 않은 트럭이 남아 있는 동안 반복한다.

주의할 점은 이 반복문이 **모든 트럭이 다리를 건널 때까지**가 아니라 **마지막 트럭이 다리에 진입할 때까지** 실행된다는 것이다.

---

### 9.5 1초 증가

```java
time++;
```

반복문 한 번이 1초를 의미한다.

매초 트럭이 한 칸 이동하고, 맨 앞에 있던 트럭 또는 빈 공간이 다리 밖으로 나간다.

---

### 9.6 다리에서 값 제거

```java
int exitedTruck = bridge.poll();
currentWeight -= exitedTruck;
```

큐 맨 앞의 값을 제거한다.

- 트럭이 나오면 해당 트럭 무게가 반환된다.
- 빈 공간이 나오면 `0`이 반환된다.

빠져나온 트럭의 무게를 현재 다리 무게에서 뺀다.

예를 들어 현재 상태가 다음과 같다고 하자.

```text
bridge = [7, 0]
currentWeight = 7
```

`poll()`을 실행하면 `7`이 제거되므로:

```text
currentWeight = 7 - 7 = 0
```

---

### 9.7 다음 트럭 확인

```java
int nextTruck = truck_weights[truckIndex];
```

아직 진입하지 않은 트럭 중 가장 앞에 있는 트럭의 무게를 가져온다.

트럭은 순서를 바꿀 수 없으므로 항상 `truckIndex`가 가리키는 트럭만 확인한다.

---

### 9.8 다음 트럭이 진입할 수 있는 경우

```java
if (currentWeight + nextTruck <= weight) {
    bridge.offer(nextTruck);
    currentWeight += nextTruck;
    truckIndex++;
}
```

현재 다리 무게에 다음 트럭의 무게를 더해도 최대 무게를 넘지 않으면 진입할 수 있다.

트럭이 진입하면:

1. 큐 뒤에 트럭 무게를 넣는다.
2. 현재 다리 무게를 증가시킨다.
3. 다음 트럭을 가리키도록 인덱스를 증가시킨다.

다리 위 트럭 수 제한을 별도로 검사하지 않는 이유는 큐의 크기가 항상 `bridge_length`로 고정되어 있기 때문이다.

매초 맨 앞 값을 먼저 제거한 뒤 새로운 값 하나만 넣으므로 다리 길이를 초과할 수 없다.

---

### 9.9 다음 트럭이 진입할 수 없는 경우

```java
else {
    bridge.offer(0);
}
```

다음 트럭까지 진입하면 무게 제한을 초과하는 경우이다.

트럭은 대기시키고, 큐에는 빈 공간을 의미하는 `0`을 넣는다.

이 경우 `truckIndex`는 증가시키지 않는다. 따라서 다음 초에도 같은 트럭의 진입 가능 여부를 다시 확인한다.

---

### 9.10 마지막에 다리 길이를 더하는 이유

```java
return time + bridge_length;
```

반복문은 마지막 트럭이 **다리에 올라간 순간** 종료된다.

하지만 마지막 트럭은 아직 다리를 완전히 빠져나오지 않았다.

다리 길이가 2라면 마지막 트럭이 진입한 뒤 2초가 더 지나야 퇴장한다.

따라서 계산된 시간에 `bridge_length`를 더한다.

---

## 10. 예제 실행 과정

```text
bridge_length = 2
weight = 10
truck_weights = [7, 4, 5, 6]
```

큐의 왼쪽을 출구, 오른쪽을 입구라고 생각한다.

| 시간 | 다리 상태 | 현재 무게 | 다음 트럭 | 설명 |
|---:|---|---:|---:|---|
| 0초 | `[0, 0]` | 0 | 7 | 빈 다리 |
| 1초 | `[0, 7]` | 7 | 4 | 트럭 7 진입 |
| 2초 | `[7, 0]` | 7 | 4 | `7 + 4 > 10`이므로 4는 대기 |
| 3초 | `[0, 4]` | 4 | 5 | 트럭 7 퇴장, 트럭 4 진입 |
| 4초 | `[4, 5]` | 9 | 6 | 트럭 5 진입 |
| 5초 | `[5, 0]` | 5 | 6 | `5 + 6 > 10`이므로 6은 대기 |
| 6초 | `[0, 6]` | 6 | 없음 | 트럭 5 퇴장, 마지막 트럭 6 진입 |
| 7초 | `[6, 0]` | 6 | 없음 | 트럭 6 이동 |
| 8초 | `[0, 0]` | 0 | 없음 | 트럭 6 퇴장 |

마지막 트럭은 6초에 다리에 진입한다.

반복문에서 계산한 시간은 6초이고, 다리 길이인 2초를 더하면:

```text
6 + 2 = 8초
```

따라서 정답은 `8`이다.

## 11. 큐와 변수의 변화 자세히 보기

2초에서 3초로 넘어가는 과정을 살펴보자.

### 2초 상태

```text
bridge = [7, 0]
currentWeight = 7
nextTruck = 4
```

### 맨 앞 값 제거

```java
int exitedTruck = bridge.poll();
```

`7`이 제거된다.

```text
bridge = [0]
```

### 현재 무게 갱신

```java
currentWeight -= exitedTruck;
```

```text
currentWeight = 7 - 7 = 0
```

### 다음 트럭 진입 가능 여부 확인

```text
0 + 4 <= 10
```

진입할 수 있으므로 트럭 4를 넣는다.

```text
bridge = [0, 4]
currentWeight = 4
```

이 과정을 반복하면 트럭의 이동을 실제 시간처럼 표현할 수 있다.

## 12. 왜 매번 큐 전체의 무게를 더하지 않을까?

다리 위 무게를 구할 때마다 큐 전체를 순회할 수도 있다.

```java
// 비효율적인 방식의 예
int sum = 0;
for (int value : bridge) {
    sum += value;
}
```

하지만 매초 큐 전체를 확인하면 다리가 길수록 불필요한 계산이 많아진다.

이 풀이에서는 `currentWeight`를 사용한다.

- 트럭이 나가면 그 무게만큼 뺀다.
- 트럭이 들어오면 그 무게만큼 더한다.

따라서 현재 무게를 매번 한 번의 계산으로 갱신할 수 있다.

## 13. 시간 복잡도와 공간 복잡도

### 시간 복잡도

반복문은 실제로 흐르는 시간만큼 실행된다.

```text
O(T)
```

여기서 `T`는 모든 트럭이 다리를 건너는 데 걸리는 전체 시뮬레이션 시간이다.

큐의 `offer()`와 `poll()`은 각각 `O(1)`에 처리된다.

### 공간 복잡도

큐에는 항상 `bridge_length`개의 값이 들어 있다.

```text
O(bridge_length)
```

## 14. 자주 하는 실수

### 실수 1. 진입할 수 없을 때 아무것도 넣지 않기

```java
else {
    // 아무것도 하지 않음
}
```

이렇게 하면 큐의 크기가 줄어들어 다리 길이와 이동 시간이 제대로 표현되지 않는다.

진입할 수 없더라도 시간이 흐르므로 반드시 `0`을 넣어야 한다.

```java
else {
    bridge.offer(0);
}
```

### 실수 2. 나간 트럭의 무게를 빼지 않기

```java
bridge.poll();
```

값만 제거하고 `currentWeight`에서 빼지 않으면 실제보다 다리 위 무게가 크게 계산된다.

```java
int exitedTruck = bridge.poll();
currentWeight -= exitedTruck;
```

### 실수 3. 트럭이 진입하지 못했는데 인덱스 증가시키기

트럭이 실제로 진입한 경우에만 다음 트럭으로 이동해야 한다.

```java
if (currentWeight + nextTruck <= weight) {
    bridge.offer(nextTruck);
    currentWeight += nextTruck;
    truckIndex++;
}
```

### 실수 4. 마지막 트럭이 진입하자마자 끝났다고 생각하기

마지막 트럭이 다리에 올라온 것과 완전히 건넌 것은 다르다.

반복문 종료 후 `bridge_length`초를 더해야 한다.

### 실수 5. 트럭의 순서를 바꾸기

더 가벼운 트럭을 먼저 보내면 더 많은 트럭을 올릴 수 있을 것처럼 보여도, 이 문제에서는 입력된 순서를 바꿀 수 없다.

항상 `truck_weights[truckIndex]`만 확인해야 한다.

---

## 15. 핵심 정리

- 이 문제는 **큐를 이용한 시뮬레이션 문제**이다.
- 다리를 길이가 `bridge_length`인 고정 크기 큐로 표현한다.
- 트럭이 없는 공간은 `0`으로 표현한다.
- 매초 큐의 맨 앞 값을 제거하고, 뒤에 트럭 또는 `0`을 넣는다.
- `currentWeight`로 다리 위 무게를 관리한다.
- 반복문은 마지막 트럭의 진입 순간 끝나므로 `bridge_length`초를 추가한다.

> 핵심 한 줄: 다리를 고정 크기 큐로 만들고, 매초 트럭 또는 빈 공간 `0`을 한 칸씩 이동시킨다.
