## 💻 깃허브 이용 규칙

### 1. 브랜치 전략

매주 새 브랜치를 만들지 않고, **본인 이름으로 된 고정 브랜치 하나**를 계속 사용합니다.

| 단계 | 할 일 |
| :--- | :--- |
| 최초 1회 | 본인 이름의 브랜치 생성 |
| 매주 작업 전 | 내 브랜치에서 `main`의 최신 내용 가져오기 |
| 작업 후 | 내 브랜치에 커밋하고 푸시 |
| 과제 제출 | 내 브랜치에서 `main`으로 PR 생성 |

**최초 브랜치 생성**

```bash
git checkout -b 본인이름
```

**매주 작업 전, 내 브랜치에서 실행**

```bash
git pull origin main
```

> 작업 전에 반드시 `main`의 최신 내용을 반영해 주세요.

### 2. 폴더 구조

**월 → 주차 날짜 → 본인 이름** 순서로 폴더를 만들어 주세요.

```text
Algorithm-Study
├── 2026-01
│   ├── 2026-01-05
│   │   ├── Gildong
│   │   │   ├── BOJ_1000.java
│   │   │   └── README.md
│   │   └── Cheolsu
│   │       └── ...
│   └── 2026-01-12
│       └── ...
├── 2026-02
│   └── 2026-02-02
│       └── ...
└── README.md
```

### 3. 커밋 컨벤션

```text
[플랫폼] 문제번호_문제이름 / 난이도 / 이름
```

| 플랫폼 | 예시 |
| :--- | :--- |
| 백준 | `[BOJ] 2557_Hello World / Bronze5 / 홍길동` |
| 프로그래머스 | `[PGS] 42862_체육복 / Lv1 / 김싸피` |

### 4. Pull Request 규칙

**PR 제목**

```text
[날짜] 이름 과제 제출
```

예시: `[260105] 홍길동 과제 제출`

**PR 내용**

- 이번 주 풀이한 문제와 특이사항 작성
- 공유하고 싶은 접근 방식이나 어려웠던 부분 정리

**코드 리뷰**

- 스터디 모임 전까지 다른 팀원의 코드에 **코멘트 1개 이상** 작성
- 질문, 개선점, 좋았던 풀이 등 공유

**Merge**

- 스터디 모임 종료 후 `main` 브랜치로 Merge

## 🔄 주간 제출 흐름

| 순서 | 진행 내용 |
| :--- | :--- |
| 01. 최신 내용 반영 | 내 브랜치에서 `git pull origin main` 실행 |
| 02. 문제 풀이 | 공통 문제 2개 + 자유 문제 1개 풀이 |
| 03. 과제 제출 | 커밋, 푸시 후 `main`으로 PR 생성 |
| 04. 동료 리뷰 | 모임 전까지 다른 팀원 코드에 코멘트 1개 이상 작성 |
| 05. 월요일 오후 9시 | 풀이 발표, 코드 리뷰, 트러블슈팅 |
| 06. 모임 종료 후 | PR을 `main`으로 Merge |
